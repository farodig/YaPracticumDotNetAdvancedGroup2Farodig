# Сервис событий
## EventService API
|Метод |Адрес            |Запрос                                         |Ответ                              |Описание                           |Доступ (Роль)|
|------|-----------------|-----------------------------------------------|-----------------------------------|-----------------------------------|-------------|
|GET   |/events          |                                               |[PaginatedResult](#paginatedresult)|Получить список всех событий       |Аноним       |
|GET   |/events/top      |                                               |List[EventResponse](#eventresponse)|Получить список топ событий        |Аноним       |
|GET   |/events/{id}     |                                               |[EventResponse](#eventresponse)    |Получить событие по идентификатору |Аноним       |
|POST  |/events          |[CreateEventRequest](#createeventrequest)      |[EventResponse](#eventresponse)    |Создать событие                    |Admin        |
|PUT   |/events/{id}     |[UpdateEventRequest](#updateeventrequest)      |                                   |Изменить событие                   |Admin        |
|DELETE|/events/{id}     |                                               |                                   |Удалить событие                    |Admin        |

## Детализация запросов
### Метод GET /events
QueryString Параметры:
- title - Поиск событий по названию (опциональный, регистронезависимый, частичное совпадение)
- from - Поиск событий которые начинаются не раньше указанной даты (опциональный)
- to - Поиск событий которые заканчиваются не позже указанной даты (опциональный)
- page - Страница, которую необходимо вернуть (опциональный, по умолчанию 1)
- pageSize - Количество элементов на странице (опциональный, по умолчанию 10)

## Кеширование событий
Для кеширования используется Redis. Настройки можно задать в appsettings.json, где:

- BootstrapServers - адрес кеша
- GeneralTtlSec - время жизни записи кеша
- TimeoutMs - время ожидания ответа при обращении к кешу

⚠️ **Важно:** время ожидание не должно быть большим, т. к. кеш призван сократить задержку а не внести её в случае неработающего сервера кеша

Пример appsettings.json

```markdown
  "Cache": {
    "BootstrapServers": "localhost:6379",
    "GeneralTtlSec": 5,
    "TimeoutMs": 200
  }
```

Кешируются следующие запросы:

- список самых популярных событий 

используется стратегия <Инвалидация при чтении>, обновляется раз в час при попытке чтения

📝 **Примечание:** обновление данных не критично, подходящий интервал от 15 минут до 1 часа

- получение события по идентификатору

используется стратегия <Обновление при записи>, время жизни записи берётся из настроек, параметр GeneralTtlSec, по умолчанию 5 секунд.

📝 **Примечание:** Кеш призван сократить время доступа, но при этом не стоит забывать что слишком долгое время хранения записи может привести к нагрузке на оперативную память, частые запросы к базе могут быть сглажены коротким хранением кешированной записи от 5 до 60 секунд.
